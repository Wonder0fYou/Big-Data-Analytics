### (а) Поиск наибольшего числа

Алгоритм делится на два этапа:
1. Mapper присваивает каждому числу ключ <bucket_id>
(abs(n) % NUM_BUCKETS), распределяя данные по reducerам.
Reducer находит локальный максимум в своей корзине и выводит его.
2. Mapper добавляет ко всем локальным максимумам ключ global_max,
направляя их в один reducer. Тот же reducer, что и в фазе 1,
находит глобальный максимум.
    
### (б) Поиск среднего арифметического

Алгоритм делится на два этапа:

1. Mapper присваивает каждому числу ключ <bucket_id>.
Reducer считает частичную сумму и количество элементов в своей
корзине и выводит пару <local_sum>\t<local_count>;
2. Mapper добавляет ключ total_avg к каждой паре.
Reducer суммирует все частичные суммы и количества и выводит
total_sum / total_count.

### (в) Исключение дубликатов

Алгоритм делится на два этапа:

1. Mapper использует само число как ключ, гарантируя, что все
вхождения одного числа попадут к одному reducerу. Reducer
выводит ключ ровно один раз при его смене.
2. Mapper добавляет ключ distinct ко всем уникальным числам,
собирая результаты всех reducerов фазы 1.
Reducer просто извлекает число из каждой строки — повторная
дедупликация не нужна, уникальность уже обеспечена фазой 1.

### (г) Подсчет различных целых чисел

Алгоритм делится на два этапа:

1. Mapper использует само число как ключ. Reducer выводит 1
при каждой смене ключа — одну единицу на каждое уникальное число.
2. Mapper добавляет ключ count к каждой единице. Reducer
суммирует все единицы и выводит итоговое количество.

## Особенности хранения ОБФЦЧ (Очень Большого Файла Целых Чисел)

**Ключевые особенности хранения:**
1. **Блочное разделение:** Файл разбивается на блоки фиксированного размера
2. **Распределенность:** Эти блоки распределяются по множеству узлов в кластере.
3. **Репликация:** Каждый блок копируется на несколько узлов. Если один сервер выйдет из строя, данные не потеряются и будут доступны с другого узла.
4. **Локальность данных:** При запуске MapReduce вычисления отправляются туда, где физически лежат данные. Это минимизирует передачу огромных объемов данных по сети.
